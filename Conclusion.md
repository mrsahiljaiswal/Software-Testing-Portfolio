# Conclusion

This portfolio tests the Vehicle Traffic Violation and Fine Management System against one locked requirements baseline. The work covers owner and vehicle registration, the driving-licence flag, challan recording, fine calculation, payment, disputes, reports, and the challan state machine.

The design uses four techniques. Equivalence partitioning separates valid and invalid classes such as licence status, helmet and seatbelt applicability, and report membership (20 cases). Boundary value analysis sits on the speed bands, zone limits, the 180-day repeat window, the dispute and payment dates, the late-penalty bands, the 5000 clearance limit, and half-up rounding (24 cases). Decision tables combine the conditions for issuing a challan and for computing a payable amount (16 cases). State-transition cases walk every allowed move and the invalid moves that must be rejected (17 cases). That is 77 manual cases. After retest, all 77 pass.

The additional automation activity is a Python `unittest` suite, chosen because the workstation has Python 3.12.6 and does not have Maven. Java 17 is present, but a JUnit run would have required a download, which this assignment does not allow. The suite has 92 tests, including a regression test for each corrected defect, and the run on 24 November 2026 is green. It shows that the current module matches the baseline: an 11 km/h overspeed is fined 1500, an unpaid total of exactly 5000 does not block registration, a private car cannot be challaned for no helmet, a dispute on day 16 stays Issued, and drunk driving does not receive the 10% early discount.

Five defects were found on Build B1 and closed on Build B2. DEF-01 shifted the inclusive speed-band edges. DEF-02 blocked clearance at exactly 5000. DEF-03 accepted a no-helmet challan for a private car. DEF-04 accepted a dispute on day 16. DEF-05 gave drunk driving the early-payment discount. The code in the repository already contains the fixes. The defect reports describe the faults as they were found and then retested. No critical defect remains open.

The limitation is the test item itself. There is no live traffic-police deployment, camera feed, or payment gateway. Manual cases were executed against the specification and the local Python module, not against a production challan database. Licence suspension is only a recommendation flag; the module does not update an external transport register. The next step for the team would be a thin officer screen over this module, with the same unittest suite kept as the regression gate, and a separate test pass for any payment-gateway adapter before that adapter was trusted with real money.

The portfolio meets the subject objectives: a written plan, technique-based cases, an execution record with defects and retests, automated tests that lock the corrected rules, and a traceability path the team can walk in the viva.
